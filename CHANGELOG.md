# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Before 1.0, minor versions may contain breaking changes.

## [Unreleased]

### Added

- Compose `extra_hosts`, `links` and `volumes_from`. Each was rejected as unimplemented while the model already had the thing it needs. `extra_hosts` takes literal IPv4/IPv6 addresses in mapping or `name:address` list form and writes them into the `/etc/hosts` block flotilla already generates for peer names; `host-gateway` is rejected at the value level (`no-model`), since a sandbox has no host to reach, and reachability still follows the egress policy. `links` publishes `service:alias` as an alias of the target on a network both are on, attaching both to `default` when they share none, as Compose does; unlike Docker the alias is visible to every member of that network. `volumes_from` adds the donor's declared mounts to this service with `:ro` folded in, does not follow the donor's own `volumes_from`, and rejects a target this service already mounts instead of silently replacing it. Manifest schema 10 adds `units[].extra_hosts`; a schema-9 release loads with none.
- `flotilla prepare --cache <dir>` (`prepare(cache=...)`) keeps image configs and image account databases between runs, keyed by image digest, so a later run does not read the same images again.
- Host `flotilla prepare` prepares `prepare.concurrency` tasks at once (`prepare(concurrency=...)`; 1 with an explicit `context`). Packaging into the release keeps row order.
- Top-level Compose `x-*` extension fields are recorded instead of rejected. The config adapter resolves YAML anchors before normalization, so a surviving `x-` key is leftover metadata; Compose strips the service-, network- and volume-level extension fields itself, so only the top level needed this.
- Compose `devices: /dev/fuse`, alongside the existing `/dev/kvm` and `/dev/net/tun`. The service runs on the privileged runtime with the `fuse` extension written per instance, gated on `runtime.fuse` in the capability report. **Breaking for deployments that set `fuse` in a static extensions table**: like `kvm` and `tun`, that key is now rejected there, because flotilla writes it per instance. The FUSE probe is correspondingly scoped like the other two — its own privileged instance requesting only that device, instead of inspecting the deployment's extension tables, where it reported `skipped` unless every privileged sandbox carried FUSE. The platform asks for no special runtime for FUSE, but this evidence is privileged-scoped, so a task declaring it runs privileged too.

### Changed

- **Breaking: a unit's environment is the task's own variables overlaid on the image `ENV`, not a copy of it.** flotilla used to read every image's config from the registry, merge its `Env` under the Compose `environment`, and send the result as the command's complete environment, which the wrapper installed with `env -i` — clearing what the container already had, then writing the same content back. Measured on the deployment: the exec daemon starts every command with the image environment the container runtime applied (same as `docker exec`), and request variables are layered on top. So the image half is no longer read or sent. Gone: `ImageMeta.env`, the `{**meta.env, **svc.environment}` merge, and `env -i` in the exec wrapper. The wrapper still carries a name sh cannot reference under an alias and now unsets that alias, and still resolves `HOME` for the identity execd applies — the passwd entry for that uid wins, else the image's own `HOME`, else `/`. `[agent_overlay].env` consequently cannot extend an image value: `${VAR}` must name something the service itself declares, and referencing anything else is an error instead of silently expanding to an empty string. `LEGACY_UNSAFE_ENV` is unchanged — it rejects a task *declaring* `BASH_ENV`/`ENV`/`SHELLOPTS`/`BASHOPTS`, which under the legacy protocol would alter execd's outer shell; an image declaring them in its own `ENV` was always out of flotilla's reach.
- **Breaking: `flotilla prepare` publishes the rows that prepared.** A failed selected row is left out of the release and reported with `status: failed`, its stage and reason; nothing is published only when no row prepared. One failure among hundreds of tasks no longer discards the run. `PrepareResult` gains `prepared` and `failed` row counts, and the CLI prints how many rows failed.
- An image `USER` or Compose `user` of `root`, `root:root`, `0` or `0:0` resolves to 0:0 without reading the image's `/etc/passwd` and `/etc/group`. Reading them created a container from the image, so preparation pulled every image declaring `USER root` only to learn that root is uid 0 with primary group 0.
- Every rejected Compose field carries a category saying what would have to change for it to become supported: `unimplemented` (Flotilla's own work), `platform-gap` (the sandbox API has no request surface), `no-model` (a sandbox is one container in one isolation domain, so the field has no subject), `out-of-scope` (a different job from orchestration), `unsafe`, `not-reproducible`, and `docker-internal`. The categories live in `normalize.py` and in the support table, and a test compares them key by key, as it already did for the key set. A field whose values span categories is marked `mixed` and takes the strictest one. Two reasons were wrong rather than imprecise: `extra_hosts` claimed the sandbox cannot map a name to an address, but every trial already has its `/etc/hosts` written to publish service names, so an entry naming a literal address is only unimplemented and `host-gateway` is the part with no counterpart; `security_opt` and `sysctls` each span both directions, since `no-new-privileges` and namespaced sysctls belong with `cap_drop` while unconfined seccomp or apparmor and non-namespaced sysctls remove the isolation the sandbox provides.
- Compose rejection reasons for fields the sandbox API has no counterpart for now say so, instead of "not supported yet" or "not seen in task data": `cap_drop`, `security_opt`, `ulimits`, `sysctls`, `extra_hosts`, `group_add`, `pid`, `ipc` and `network_mode: service:`/`container:`. `pids_limit`, `dns`, `dns_search`, `dns_opt`, `platform`, `memswap_limit` and `cgroup` were previously unclassified and fell through to a generic "unsupported field"; they are now listed with their reason and appear in the support table.

### Removed

- **Breaking: named volumes no longer emulate Docker's copy-up; manifest schema 9.** Docker copies the image content under a mount target into a fresh named volume. Flotilla used to reproduce that: it read every service image during preparation, compared the extractions of all copy-enabled references, packed the winner into `files/seeds/<volume>.tar`, and had the trial `tar -xpf` it into the volume. A named volume now starts empty, and `TrialVolume.owner` declares its root identity. `volume.nocopy: true` becomes **equivalent** rather than a supported option: it asks for what already happens. Gone: `TrialVolume.seed` (schema 8 migrates when it is empty and refuses a release that populated it), `Exported.seeds`, the `ImageExport` protocol and `BuildContext.image_export`, `DockerImageExport.extract` and `extract_archive`, `Anchor.unpack`, `VolumePlan.nocopy`, `VolumeMount.nocopy`, the `image_extract` and `seed_cache_copy` metric phases with the `seed_cache_hits` count, `flotilla.testing.build.FakeExport`, and `tests/contract/docker_metadata.py`. `DockerImageExport` is now `DockerImageAccounts`: preparation still runs Docker, because a named Compose `user:` resolves through the image's `/etc/passwd` and `/etc/group`.
- **Breaking: flotilla no longer builds, adapts or publishes images.** Preparation consumes images that are already published, so it needs no builder, no push target and no registry write access. Gone: `build/builder.py`, `build/cache.py`, `build/dockerfile.py`, `build/keys.py`, `DockerBuilder`, `Registry.find`/`Registry.copy`, `resolve_images`, the `link`/`mirror`/`config-only`/`cache-hit`/`built` dispositions, `BuildContext.builder`/`.adaptations`/`.user_lookup`, `BuildOutcome.built`/`.adapted`/`.dispositions`, the `build.target`, `build.mirror_images`, `build.oci_mediatypes` and `build.attestations` settings, `--image-repo`, `--require-prebuilt-images`, and the `image_preflight`, `registry_lookup`, `registry_copy`, `user0_build_push` and `application_build_push` metric phases with the `build_cache_hits` and `config_only` counts. `flotilla.testing.build.FakeBuilder` is gone; `FakeRegistry` keeps digest resolution and image configs.
- **Breaking: Compose `build:` is rejected (`out-of-scope`).** A Harbor task without `[environment].docker_image` whose environment holds a `Dockerfile` is rejected during selection instead of being built. Publish the image first and name it. `Service.build` and the `Build` model are gone.
- **Breaking: a non-root image is rejected instead of adapted.** flotilla used to build `FROM <source digest>` / `USER 0:0` and push it, because the exec daemon is the sandbox entrypoint and needs root. It now reports the image's `USER` and refuses the task: publish the image with `USER 0:0` and declare the application identity with Compose `user`, which preparation already resolves to numeric uid/gid. `provenance["adaptation"]` is no longer written.
- **Breaking: the legacy Harbor source-task API.** `HarborAttempt`, `HarborVerification`, the `prepare/runner.py` and `share/publish.py` entry points, the compile/restore half of `flotilla.integrations.workspace`, and the `WorkspaceStore` file operations only they used. `flotilla.integrations.workspace` keeps its metadata/describe path. Task executions enter through `NativeAttempt` with a native release binding.
- **Breaking: the in-repo Compose parser.** `compose_adapter` is now a required argument to `load_task` and `load_environment`, so every project is resolved by the pinned `docker compose config`. `compose/interpolate.py`, `runtime/values.py`, `RuntimeExpression`, the `variables`/`resolved` parameters of `normalize()`, `harbor_overlay`, `HARBOR_VARIABLES`, and the `compose/resources.py` and `compose/units.py` re-export shims are gone. Fixtures that need offline resolution use `flotilla.testing.compose.OfflineComposeAdapter`.
- **Breaking: runtime parameters.** `OpenOptions.runtime_params`, `RunRequest.runtime_params` and `Manifest.runtime_params`. Every reference is resolved at preparation. Manifest schema 8 migrates a schema-7 manifest with an empty list and rejects one with a populated list, which must have its release prepared again.
- **Breaking: preparation no longer inspects tmpfs and read-only runtime mount targets in the image.** `BuildContext.validate_mount_paths`, `DockerImageExport.validate_mount_paths`, the `mount_path_inspection` metric and `FakeExport(links=...)`/`FakeExport.inspected` are gone. The check created a container per service (pulling its image) to reject a symlinked or non-directory target; the container runtime already resolves a symlinked mount target inside the container's root filesystem, as Docker does, and a regular-file target fails at sandbox creation.
- Unreachable symbols: the `Backend.profile` / `FlotillaConfig.filesystem_profile` hook chain, `compile_host_volumes` and `compile_pvc_volumes` (use `StorageSettings.compile`), `derive_dockerfile`, and `share.release.release_json`.

### Fixed

- A native release prepared against manifest schema 7 loads again. Schema 8 dropped two fields, but the migration stripped only `runtime_params`; every such release also carries `task_files_published`, which `extra="forbid"` then rejected, so binding any existing release failed. Both are now dropped when empty and refused when populated.
- An undefined Compose variable is refused again. The in-repo parser rejected it, but `docker compose config` substitutes a blank string and exits 0, and both backstops for the deferred form were unreachable, so a task referencing `${TAG}` with no value baked an empty string into its release. The adapter now reads Compose's own "variable is not set" warning and fails the task; a reference with a default (`${VAR:-x}`) is unaffected.
- `flotilla inspect` loads through the deployment's pinned Compose tool, so its findings and resources match what preparation computes for the same task. It previously used the in-repo parser and could disagree.
- `OfflineComposeAdapter` refuses interpolation and `env_file` instead of leaving a `${VAR}` reference to reach `normalize()` as a literal string.

### Changed

- **Breaking: native release format v2.** A release is a plain directory: `dataset.jsonl` plus `tasks/<task-key>/{task.json,instruction.md,files/,tests/}`. There is no `manifest.json`, no content addressing, no per-file inventory and no `release_id`/`task_digest`. Rows are `{release, task, annotations, parameters}`; `release` names the `[task_releases.<name>]` binding. Version 1 releases must be prepared again.
- Consumers read only `task.json` and `instruction.md`; nothing is hashed locally, and launches no longer run the Anchor-side `platform_verify` check (the installed helper keeps `--clear-directory` and `--self-test`, so existing Anchor images keep working). The 16 MiB metadata limit is gone, so one release holds any number of tasks.
- `flotilla prepare` takes `--name` and drops `--resume`/`--work-dir` and the input fingerprint; work files live in a temporary sibling directory removed afterwards. File owners are not recorded or applied; modes are kept.
- The Compose executable's version is checked once per process instead of once per task.
- `[share]` is optional. Without it a deployment uses the built-in release `busybox-1.36.1-r31`, which probe and runtime start publish into the work root from the Anchor image's pinned BusyBox when missing (no network). Explicit `[share]` pins keep working.
- A capability report measured with different deployment settings (`evidence_profile`) is no longer rejected; runtime start logs a warning. The report schema is unchanged.
- `[agent_runtime].layers.<name>.local_root` is optional; layers can be identified by `platform_root` alone.
- Compose fields that only change local Docker behavior are recorded instead of rejected: `init`, `logging`, `stop_signal`, `stop_grace_period`, `pull_policy`, `ports`, network `gw_priority`, bridge name/MTU/`gateway_mode` options, and `depends_on.*.restart`. `restart` `always`/`unless-stopped`/`on-failure[:N]` never restart and void the run on an exit Docker would restart. `hostname` (warning) and `container_name` become resolvable names. Harbor `storage_mb` is a selection warning.
- `flotilla prepare` reuses base digests for config-only Dockerfiles and publishes other builds under content-keyed `bk-<key>` tags that later runs reuse; USER0 adaptations are reused by tag. Prepare reports carry per-service `dispositions` (`link`, `mirror`, `config-only`, `cache-hit`, `built`) and `adapted`; selection reports carry image sources and warnings. `BuildOutcome.dispositions` no longer marks adapted services as `build`; see `adapted`.
- `Registry` gains `find(name, reference)`, returning `None` for a missing tag.
- A named volume with several copy-enabled sources is seeded when the extracted sources agree: absent or empty paths contribute nothing, and only differing contents or root identities are rejected.
- Volume seeds keep symlinks that resolve inside the volume; symlinks leaving it and entries reached through a symlinked directory are rejected with a field path.

### Added

- `flotilla.Deployment`: one consumer entry point for a deployment. `Deployment.load(path, credentials=...)` binds only the deployment's `credential_env` variable from a literal `KEY=value` file; the object provides `client()`, `release_bindings()`, `setup_budget()`, `run_timeout()`, `client_overhead()`, `dataset_peak(rows)`, `validate(rows, sandboxes=..., options=...)` (starts every role except a separate verifier, so shared-verifier tasks are exercised too), `storage_identity(root)`, `runtime_layers()` / `runtime_options(...)` for read-only `[agent_runtime]` mounts on the agent service, and `freeze(dir)`, which writes a portable `deployment.json` plus its capability report. Consumers no longer need to read backend tables, timeout names or storage settings.
- `FlotillaConfig.load` reads `.json` configurations (frozen copies); `flotilla.environment.read_env_file` parses a credential file without changing the process environment.
- Support caller-owned external read-only mounts via `OpenOptions.external_mounts` and `RunRequest.external_mounts`. Mounts are verified for read-only flags, non-overlapping target paths, and key hygiene, and are excluded from trial volume lifecycle management (no seeding, chowning, or cleanup deletions).
- `prepare.export_timeout` (default 600 s, the previous fixed value) bounds each `docker cp` that exports an image volume's initial content, so tasks with large volumes can be prepared. Export failures now include docker's error output.
- `flotilla prepare`: builds images and publishes task files once per task, offline, and writes a jsonl with one row per task (`load_prepared`, `PreparedTask`, `PreparedEnvironment`). Rows carry filter attributes and the digest-pinned main and separate verifier environments; filtering a dataset is filtering lines. Interrupted runs resume, `--force` rebuilds, and each dataset's images go to `<build.target>/<dataset>`. Task files are published flat under `tasks/<dataset>/<task>/<role>`.
- Pluggable sandbox backends. A package registers a `flotilla.backends.Backend` subclass in the `flotilla.backends` entry-point group; a deployment selects it with `backend = "<name>"` and configures it in `[backends.<name>]`. The built-in OpenSandbox backend keeps its `[opensandbox]` table, and existing configurations and capability-report fingerprints are unchanged. See [Writing a backend](docs/Writing_a_Backend.md).
- Opt-in internal lifecycle support for Compose read-only root filesystems and native tmpfs, with independent behavioral probes, effective-configuration verification, private framework scratch mounts, and strict upstream-compatible request defaults.
- Compose `privileged: true` (warning): the service runs on the privileged runtime and is admitted with passed privileged isolation evidence. The Docker check is now only a recorded measurement in `runtime.privileged_runtime`.
- Compose `devices` `/dev/kvm` and `/dev/net/tun` (plus `cap_add: [NET_ADMIN]` alongside TUN). Such services run on the privileged runtime with per-instance `kvm`/`tun` extensions, carried through the manifest (`Unit.devices`), plan and `InstanceSpec.devices`. The privileged probe phase measures `runtime.kvm` and the new `runtime.tun` on one instance per device; preparation and admission require that evidence. The extension keys `kvm` and `tun` are no longer accepted in static extensions tables. Trial volumes mounted writable by privileged-runtime units are opened with `chmod -R a+rwX` before creation (sysbox root does not own anchor-created storage). The privileged probe phase now runs with only `probe.privileged_image`; the Docker check (`inner_image`) gates `privileged: true` services but no longer the isolation, FUSE or device checks.
- Compose `shm_size` on the internal filesystem dialect, sent per instance as the `sandbox-system.io/shm-size` extension, sharing the tmpfs memory budget, gated by the new `probe_shm_size` measurement, and verified per instance against the size the platform echoes before startup. Upstream OpenSandbox has no equivalent setting and rejects such tasks.

- Task-level `network_mode = "no-network"` and `allow_internet = false`, preserving service links while removing external access throughout preparation and execution.
- Explicit cluster DNS declarations: offline policies tolerate only the declared resolver IPs on TCP/UDP 53 and reject every other implicit egress exception.
- Opt-in sandbox ingress enforcement using the shared OpenSandbox lifecycle route. Compose `network_mode: none` now checks both outbound exceptions and inbound isolation; upstream requests retain the standard egress-only schema by default.
- Correlated execd request timing logs for send, response headers, command ID, and stream closure, without command contents or credentials.
- Compose `${VAR:+alt}` / `${VAR+alt}` and nested references inside defaults and alternatives, plus Harbor's `CONTEXT_DIR` interpolation variable (the environment directory).

### Changed

- Runtime expressions are stored once per service environment variable, with referenced build-time values kept separately as literals. New manifests use schema 7; schema 6 rows are converted on read. Redundant Compose-user mappings, the unused bind `create_host_path` model field, single-phase network-policy scaffolding, and obsolete fake-registry history methods are removed.
- `flotilla gc` finds launches from sandbox labels as well as `launches/`, and when its anchor cannot start it deletes sandboxes by label only (`GcReport.mode = "platform"`, `directories_skipped`) and exits 1. With an anchor it also removes `tasks/.staging`, `tasks/.trash` and `share/staging` entries older than `--staging-age` (default 24 h). Share release staging names now carry a timestamp.
- `CleanupRecord` gains `reason` and `error`, naming what is still unconfirmed and the last related error.
- **Breaking:** an open's budgets are split by phase. Waiting for a `trial_concurrency` / `instance_budget` slot is bounded by `OpenOptions.admission_timeout` (default `limits.admission_timeout`, 3600 s) and raises the new `AdmissionTimeout` (a `TimeoutError`) with the current counts. `startup_timeout` now starts at admission, so queueing no longer consumes it. Client start (anchor and share check) is bounded by the new `timeouts.client_start` (300 s) instead of `timeouts.prepare`.
- The share check at client start downloads only `RELEASE.json`, compares its sha256 and confirms `bin/busybox`. Per-file verification stays in `flotilla share verify`.
- **Breaking:** opening no longer prepares anything. `fleet.open(prepared)` / `fleet.environment(prepared)` take a `PreparedEnvironment` from a prepared row and run no Docker, builds, or uploads; `open_task`, `open_environment`, `inspect`, `inspect_environment`, `EnvironmentDefinition`, `EnvironmentInspection`, `OpenOptions.force_build`, `PreparationResidual` and `CleanupReport.preparation_residuals` are removed. Use `fleet.reservation(prepared)` for admission budgets and `flotilla inspect` for Docker-free checks.
- **Breaking:** `[preparation]` is removed and rejected with a migration message: `docker_command` and `concurrency` move to `[prepare]`, and `timeout_s` becomes `runtime.startup_timeout_s` (default 1800 s), the default open budget.
- **Breaking:** the Harbor adapter takes `--ek prepared=<jsonl>` and opens the row's environment for the environment directory Harbor gives it; `force_build` is rejected.
- `flotilla probe`, `gc`, and `share` construct their platform through the same factory as the runtime, so `opensandbox.privileged_extensions` now also applies to privileged instances these commands create.
- tmpfs now requires native support; the previous empty-directory approximation is removed without fallback. Private preparation manifests use schema 5 and must be regenerated.

### Fixed

- Recover transient or unknown transport responses for read-only anchor `stat` within five attempts and a 30-second retry-admission window. Preserve metadata results during recovery without replaying their helper, writes or workloads; retain existing bounded HTTP download retries without adding an outer retry layer.
- Recover bounded native Harbor metadata reads after `ESTALE`, using fresh parsing and a shared request wait budget without replaying copies, Compose/build commands or workloads. Surface tree-enumeration errors instead of silently validating incomplete trees; preserve all-or-nothing metadata publication and original failures on exhaustion.
- Healthchecks propagate non-retryable execution errors, including unknown outcomes, instead of running another check and potentially declaring the environment healthy. Public foreground/background calls preserve environments after an explicit `CommandBusy` rejection.
- Services with both `service_healthy` and `service_completed_successfully` dependents now drive both conditions independently.
- Shared named-volume seeds retain root-directory ownership and permissions, including for empty image directories. Nested runtime defaults and alternatives retain referenced `.env` values. Reprepare affected tasks to regenerate their files and expressions.
- Forced preparation invalidates selected old rows before replacing task files, so an interrupted rebuild resumes rather than skipping inconsistent output. Preparation recovers incomplete final JSONL appends while still rejecting corrupt complete rows.
- Each prepared task uses a separate temporary directory, avoiding collisions between nested and hyphenated task IDs. Cancellation waits for in-flight builder/file work before removing that directory.
- A sandbox no longer expires while its environment is still starting. Sandboxes are renewed only once the environment is ready, but they were created with `reaper.trial_ttl` (1800 s by default), so an open whose startup ran past that TTL (for example `startup_timeout` above 1800 s, or long health checks) had its sandboxes reclaimed by the platform mid-start and failed with "instance vanished during start". Each sandbox is now created with at least the open's startup budget plus `reaper.renew_before_s`.
- Environment variable names that are not shell identifiers but that Docker accepts (for example `discovery.type` or `APT::Get::AllowUnauthenticated`) are no longer rejected. The OpenSandbox exec wrapper passes them to execd under internal `FLOTILLA_ENV_<n>` aliases and restores the original names when it clears the environment. Values still travel only in the request `envs`. Names that are empty, contain `=` or NUL, start with `-`, or start with `FLOTILLA_ENV_` are still rejected.
- A sandbox the platform never starts no longer holds its trial and quota for the whole `timeouts.create` budget. After `timeouts.pending` (new, default 300 s) it is deleted and created again once, through the existing recreate path; a second stall fails the open.
- Commands waiting for a free HTTP connection are no longer counted as sent and no longer run down their timeout while they wait. Previously a burst of internal commands (for example every environment's health check at once) queued inside the 100-connection pool, expired there, and was reported as an unknown outcome, so healthy environments were marked lost. Requests now wait in Flotilla for one of `opensandbox.max_connections` (new, default 100) connections per pool.
- A create request whose response was lost no longer holds its trial for the whole `timeouts.create` budget. The request now has its own `timeouts.create_request` (default 60 s), after which the sandbox is found by its labels and adopted; previously the request timeout equalled the stage timeout, so this recovery could never run.
- Preserve non-root image `USER` for workload execution while preparing a root-default runtime image for the exec daemon, including linked and mirrored source images.
- Retry confirmed timeouts of the internal no-op health probe within the existing check budget instead of immediately losing the environment; user commands are never replayed.
- Treat execd command-stream `409 CONFLICT` responses as explicit `CommandBusy` rejections: healthchecks skip that round, foreground and background calls preserve the rejection, and commands are never automatically replayed. Other conflicts retain their existing classification.
- Send each sandbox's execd access token when replacing its network policy. Upstream OpenSandbox's Docker runtime serves `PUT /sandboxes/{id}/networkpolicy` through execd's proxy and rejected the unauthenticated request with HTTP 401, so linking multi-service environments failed.
- Stop doubling line terminators in command output from execd 1.1.1 and later, which keeps each line's terminator in stdout/stderr events.

## [0.1.1] - 2026-10-20

Initial public release plus downstream orchestration contracts.

### Added

- Async Python API (`Flotilla`, `open_task`, `open_environment`, `environment`) for running a Compose task as one sandbox per service, with confirmed cleanup reports.
- Command execution with explicit argv, identity, and environment; background processes; binary file and directory transfers.
- Cancellation and timeout semantics that never replay commands and report unknown outcomes as `ExecOutcomeUnknown`.
- Automatic image preparation with Docker BuildKit, including digest resolution, mirroring, and derived images.
- Explicit network policies (`none`, allowlist, `any`) with CIDR or sandbox-ID peer links.
- OpenSandbox backend supporting the `current` and `legacy` execd protocols.
- CLI: `inspect`, `probe`, `gc`, and `share publish|verify|gc`.
- Optional Harbor 0.24.0 environment adapter (`flotilla.integrations.harbor:FlotillaEnvironment`).

- Environment-specific inspection and public resource reservations, including per-client anchor overhead.
- Process waits with bounded observation timeouts, and explicit stop with confirmed termination.
- Public `flotilla.testing` helpers for downstream contract tests, separate from runtime imports.
