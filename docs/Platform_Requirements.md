# flotilla 对沙盒平台的能力要求

> 本文写给沙盒平台的开发与运维团队：flotilla 需要平台**提供什么、保证什么**，每项怎么验收，做不到时 flotilla 怎么处理。
> 要求与具体平台无关，不出现任何平台的 URL、字段名或规则写法；某个平台怎么满足、现状如何，写在后端文档里（目前只有 `backends/opensandbox.md`）。
>
> | 文档 | 内容 |
> |---|---|
> | `PRD.md` | flotilla 做什么、为什么 |
> | `Architecture.md` | flotilla 怎么做；它对平台的抽象接口 `Platform` |
> | 本文 | 平台必须提供的能力 C1–C16 |
> | `backends/opensandbox.md` | OpenSandbox 兼容平台：每项能力的实现方式、各部署的实测现状与缺口 |

---

## 1 一页概览

flotilla 把一个 Docker Compose 任务环境运行成**一组 sandbox，每个服务一个**。它自己负责服务的启动顺序、健康检查、服务名解析与回收；
需要平台提供的是：创建和管理单个实例、在实例里执行命令、让一组实例按指定的网络拓扑互通且与外界隔离、共享存储，以及这些行为的**可确认的保证**。

| 能力 | 一句话要求 | 类别 | 验收方式 |
|---|---|---|---|
| C1 实例生命周期 | 创建、查询、删除、续期；按标签列出且结果在声明时限内完整 | 必需 | 测得 |
| C2 执行与文件 | 对任意镜像，以指定身份、目录、环境执行命令，读写文件 | 必需 | 测得 |
| C3 后台进程 | 后台启动进程，按 ID 查询状态与退出码 | 必需 | 测得 |
| C4 组内互联 | 一组实例按拓扑互通、不同网络之间隔离；生效可确认；跨节点、跨集群都成立 | 功能（多服务） | 测得 |
| C5 入站隔离 | 组外任何实例与外部主机都连不进组内成员 | 安全 | 测得 + 声明 |
| C6 外部出站 | 每个实例的出站按 `none` / `any` / `allowlist` 执行 | 必需（`none` 与另一种至少其一） | 测得 |
| C7 实例地址 | 每个实例有一个组内可达、生命周期内不变的地址 | 功能（多服务） | 测得 |
| C8 共享存储 | 挂载共享根目录下的子目录；只读、子目录隔离、跨节点共享 | 必需 / 功能 / 安全（按子项） | 测得 + 声明 |
| C9 执行通道鉴权 | 执行通道对所有到达路径都校验按实例下发的凭证 | 安全 | 测得 |
| C10 资源限制 | 内存上限等于给定值；CPU 上限不低于给定值，实际执行方式如实声明 | 必需（内存）/ 降级（CPU） | 测得 |
| C11 容量 | 部署声明存活数、创建速率、执行调用量等容量 | 规模 | 声明 + 压测 |
| C12 诊断 | 失败与长时间等待的实例带可读原因 | 降级 | 测得 |
| C13 平台基础设施访问 | 平台为自身隐式放行的目标、端口、协议，由部署完整声明 | 必需 | 声明 + 抽测 |
| C14 可选运行时 | 特权运行时、设备等，按子项 | 功能 | 测得 |
| C15 镜像来源 | 从私有仓库按 digest 拉取 | 必需 | 测得 |
| C16 多容器实例 | 多个镜像组成一个实例、共享 namespace | 功能（首版不使用） | 测得 |

## 2 术语

| 术语 | 含义 |
|---|---|
| 实例 | 平台上的一个 sandbox |
| trial | 一个任务环境的一次运行，由若干实例组成 |
| 单元 | trial 中的一个实例，对应 Compose 的一个服务 |
| 组 | 同一 trial 的全部单元；flotilla 在创建时给每个实例打上组标签（`flotilla/trial`） |
| 网络、拓扑 | 网络是组内单元的一个子集；拓扑是一组网络。共享至少一个网络的两个单元应互通，否则应隔离 |
| 互联调用 | flotilla 把一个组的拓扑交给平台、让它生效的那次调用；每个 trial 一次 |
| 外部出站策略 | 单个实例对组外（平台之外）目标的访问范围，创建时给定 |
| 执行通道 | 平台提供的执行命令、管理后台进程、读写文件的接口，flotilla 经平台网关访问 |
| 共享根目录 | 部署给 flotilla 使用的一个共享存储目录；实例只挂其中的子目录 |
| share | 共享根目录下的一个只读目录，放 agent 运行时等与任务无关的文件，每个单元都挂载 |
| 锚点 | flotilla 每个进程起的一个小实例：挂载共享根目录做目录操作，并作为进程存活的心跳 |
| 能力报告 | 一个部署对本文各项的满足情况。由 `flotilla probe` 运行验收得到（**测得**），测不到的由部署者书面给出（**声明**） |
| 部署 | 一个平台实例（例如一个 OpenSandbox 部署），对应一份能力报告 |

## 3 类别

每项能力（或其中一条）属于以下一类。类别决定缺失时 flotilla 怎么做，不代表重要程度：

| 类别 | 含义 | 缺失时 flotilla 怎么做 |
|---|---|---|
| **必需** | 所有 trial 都依赖 | 拒绝使用该部署 |
| **功能** | 只有部分任务依赖（多服务、共享卷、特定 Compose 字段） | 在该部署上拒绝依赖它的任务，其余照常 |
| **安全** | 能运行，但 trial 之间或 trial 内部的隔离变弱，reward 可能失真 | **默认拒绝**该部署；负责人在配置中逐项显式接受后照常运行，报告与每个 trial 的元数据都标出 |
| **规模** | 不影响单个 trial 的正确性，决定能同时运行多少 trial | 按部署声明的容量设置限流 |
| **降级** | 缺失时仍然正确，只是诊断、效率或可比性变差 | 能力报告标出，不拒绝 |

安全类默认拒绝，是因为训练产出的 reward 事后难以甄别：默认放行，"这个部署能否用于正式训练"就没有人做决定。

所有能力都**不由 flotilla 补足**：flotilla 不用隧道、代理、额外的端口规则、流量探测或固定等待来代替平台能力。

## 4 能力要求

每项按"要求 / 类别 / 为什么需要 / 验收"给出。要求只规定**结果**，不规定平台怎么实现。

### C1 实例生命周期

**要求**

1. 按镜像创建实例，可指定入口命令、标签、有限 TTL、资源限制（C10）、卷（C8），以及原样透传的部署参数（放置、资源池等）；
2. 按 ID 查询状态与过期时间，开销不随部署内实例总数增长；删除，对不存在的 ID 视为成功；
3. 按标签过滤列出实例（多个条件取"与"），能翻页取全；
4. **列表可见时限**：部署声明一个时限 T（建议不超过 60 秒）。从客户端发出创建请求起 T 秒之内，这个请求要么已在列表中出现对应实例，要么永远不会产生实例：
   - T 包含平台排队、接受、镜像拉取（若拉取期间实例不在列表中）与列表同步的全部延迟；
   - 客户端超时或断开不延长 T——请求在 T 之后才被平台接受，同样违反本条；
5. 续期到指定时间，续期后查询返回新的过期时间；
6. 标签值至少支持 63 个字符；TTL 上限至少 6 小时，或可以续期。

**类别**：必需。

**为什么需要**：创建请求超时时，flotilla 按标签列出来判断实例是否已经建出来（建了就接管，没建才重试）；进程崩溃后，别的进程靠列表找到并清理它留下的实例。
列表不完整，或者"多久之后才完整"没有上界，就会漏删或误删。列表只在这几种场合使用，频率低；运行中的存活确认用按 ID 查询。

**验收**

- 测得：创建后立即按标签列出，在 T 内出现；翻页取全的结果与直接计数一致；续期后查询的过期时间更新；删除不存在的 ID 成功；
- 声明：T 的取值，以及"超时或断开的创建请求不会在 T 之后才被接受"。

### C2 执行与文件

**要求**

1. 对任意镜像提供执行通道，不要求镜像预装平台组件；对镜像的前提（例如需要 `/bin/sh`）由部署声明；
2. 以指定的 argv、uid / gid、工作目录、环境变量执行命令，返回输出与退出码；命令有超时，超时后被终止；
3. 命令除请求给的环境变量之外，若还继承了平台组件的环境，部署须声明继承了哪些；其中不能有 C9 的凭证；
4. 上传、下载任意路径的文件；`/etc/hosts` 可写，平台在运行中不重写它；
5. 实例的入口命令可以是一个占位进程，业务进程之后经执行通道启动。

**类别**：必需。

**为什么需要**：sandbox 里不运行 flotilla 的任何进程。业务进程的启动、健康检查、服务名解析（写 `/etc/hosts`）都由 flotilla 经执行通道从外部完成；
业务进程要以 Compose 声明的用户、工作目录与环境运行，与 Docker 下一致。

**验收**（测得）：以非 root 的 uid / gid、指定工作目录执行，读回 `id` 与 `pwd`；带环境变量执行并读回；超时的命令被终止；
写入 `/etc/hosts` 后读回一致，10 分钟后仍一致；以非 root 身份写文件，属主与权限正确。

### C3 后台进程

**要求**：后台启动进程（参数同 C2），按进程 ID 查询运行状态与退出码；在执行通道的整个生命周期内都能查询。

**类别**：必需。

**为什么需要**：业务服务是后台进程；flotilla 要知道一次性服务（例如数据库初始化）何时以什么退出码结束，才能启动依赖它的服务。

**验收**（测得）：后台进程运行中查询为运行中；退出后查询得到正确的退出码。

### C4 组内互联

这是 flotilla 对平台最核心的要求：flotilla 给出一组实例与它们的拓扑，平台让拓扑成立。

**要求**

1. **语义**：互联生效后，至少共享一个网络的两个成员之间，经 C7 的地址以任意 TCP 端口可达；不共享任何网络的成员之间不可达；不额外限制端口；各成员的外部出站策略（C6）不变；
2. **UDP**：同上，对 UDP 同样成立；
3. **与放置无关**：可达性与实例被调度到哪个节点、集群、资源池无关。flotilla 不选择放置，也不因放置删除重建；
4. **生效可确认**：互联调用成功返回时拓扑已对新连接生效；或者平台异步生效，但提供可查询的完成状态。两者都没有时视为不满足——flotilla 不用固定等待或连通探测代替；
5. **幂等**：以相同参数重复调用结果相同（flotilla 在调用失败时原样重试）；
6. **规模**：部署声明单组成员数上限与每个成员可属于的网络数上限；目标是每组至少 10 个成员、每个成员至少 3 个网络。

flotilla 每组只调用一次，成员不减少，删除实例前不撤销互联，所以不要求运行中替换拓扑或撤销。

**类别**：1、3、4、5 对多服务任务是功能类（单服务任务不调用互联）；2 是功能类（声明 UDP 的任务）；6 是规模类（成员数超过上限的任务被拒绝）。

**为什么需要**：Compose 中服务按网络互通（`app` 连 `db:5432`）、不共享网络的服务互不可达。这是任务环境的语义，
flotilla 把它交给平台执行，自己不在 sandbox 里运行网络组件。"生效可确认"决定了 flotilla 何时可以启动业务：业务在网络生效前启动，会把启动顺序的问题变成偶发的连接失败。

**验收**（测得）：三个成员两个网络（A–B 同网、B–C 同网、A–C 不同网）：生效后立即测 A↔B、B↔C 的 TCP 与 UDP 任意端口可达，A↔C 不可达；
把成员放到不同节点、不同集群后重复。

### C5 入站隔离

**要求**

1. **初始隔离**：实例从可以执行命令起，到第一次互联之前（单服务实例则是整个生命周期），不能与任何其他实例互通；
2. **组外不可入**：组外的任何实例（其他 trial、平台上的其他租户、不是 flotilla 创建的实例）与平台外的主机，都不能主动连入组内成员的任何端口；组内成员对外发起的连接的回程不受影响。
   实现方式由平台选择，例如入站过滤、所有实例默认拒绝、flotilla 专用的项目或网段；
3. **不可绕过**：实例内的 root 不能绕过上述隔离与 C6 的出站策略，例如设置平台用于豁免自身流量的包标记、改写过滤规则。
   需要特权运行时（C14）的实例若能做到这一点，部署须声明它另有隔离。

**已知例外**：按地址放行互联的实现中，成员被删除后其地址若分给别的实例，同组尚未删除的成员仍能连到那个新实例，直到它们也被删除。flotilla 接受这个窗口，不要求平台消除。

**类别**：安全（单服务与多服务 trial 都依赖）。

**为什么需要**：其他 trial 的 agent 若能连进本 trial 的服务，就能干扰本 trial 的结果，reward 失真。

**验收**

- 测得：新建实例在互联前连不到、也不能被任何实例连到；以"入口一启动就向另一实例发起连接"的镜像创建实例，连接全部失败；另起一组实例连接本组成员的监听端口，全部失败；
  实例内 root 尝试已知的绕过手段，全部失败；
- 声明：测试覆盖不到的部分（例如其他租户的实例）。

### C6 外部出站

**要求**：创建实例时给定它对组外目标的出站策略，有三种形式：

1. `none`：不能访问任何外部目标（平台自身的基础设施访问见 C13）；
2. `any`：能访问任意外部地址与域名，但**不因此**能访问组外的其他实例（C4、C5 的隔离不变），也不能访问平台自身的基础设施（节点、编排系统 API、平台控制面、云元数据等），C13 声明的除外；
3. `allowlist`：只能访问列出的 IP / CIDR 与域名；
4. 策略在实例可以执行命令之前已生效；之后的互联调用不改变它，也不使 `allowlist` 中已解析的域名失效。

**类别**

| 条 | 类别 | 原因 |
|---|---|---|
| 1、4 | 必需 | 只在 Compose `internal` 网络中的服务、不联网的服务与锚点都用 `none` |
| 2、3 | 至少提供其一，为必需 | 训练要让负责访问推理网关的服务出网；只提供其一时，要求另一种的配置被 flotilla 拒绝 |

**为什么需要**：Compose 的 `internal` 网络不能出网；其余服务按训练侧配置出网（任意外网，或只放行推理网关）。

**验收**（测得）：`none` 下外网 IP 与域名都不可达；`any` 下外网可达，组外实例与平台基础设施地址不可达（含域名解析到实例网段的情况）；
`allowlist` 下只有列出的目标可达；解析一次 `allowlist` 中的域名后做一次互联调用，以缓存的地址建立新连接仍然成功。

### C7 实例地址

**要求**：每个实例有一个地址，C4 互通的对端经它访问；控制面能取得它（经平台接口，或经执行通道从实例内读取）；在实例生命周期内不变。

**类别**：功能（多服务任务）。

**为什么需要**：flotilla 把对端的地址写进每个单元的 `/etc/hosts`，服务按服务名访问对端。

**验收**（测得）：取得的地址与对端实际看到的来源地址一致；实例运行 1 小时后不变。

### C8 共享存储

**要求**：以"共享根目录 + 相对子路径"指定挂载。

| 条 | 要求 | 类别 | 为什么需要 |
|---|---|---|---|
| 1 只读挂载 | 多个实例只读挂载同一目录；只读对实例内的 root 同样生效 | 必需 | 每个单元都只读挂载 share |
| 2 读写共享 | 多个实例读写挂载同一目录，跨节点看到同一份数据，写入的属主与权限保留 | 功能 | Compose 中多个服务共用的卷 |
| 3 子目录隔离 | 实例只能看到自己挂载的子目录，看不到共享根目录的其他部分 | 必需 | 否则任务代码能看到其他 trial 与其他任务的文件 |
| 4 缺失目录 | 子路径不存在时明确报错或自动创建，不能无限期停在等待状态 | 降级 | flotilla 总是先建好目录；缺失时只影响出错时的诊断 |
| 5 不自动挂载 | 平台不向实例自动挂载任何未声明的可写目录 | 安全 | 否则不可信代码能改写 share 与其他 trial 的卷 |
| 6 目录管理 | flotilla 能创建、初始化、删除共享根目录下的子目录（经挂载共享根目录的锚点，或平台接口） | 必需 | trial 的卷要在实例创建前准备好、结束后删除 |
| 7 文件挂载 | 子路径可以指向单个文件 | 功能 | Compose 中挂载单个文件的 bind |

**验收**

- 测得：只读挂载下 root 写入失败；实例内只见所挂子目录；锚点能建、删子目录；两个节点上的实例读写同一子目录互相可见；子路径指向文件时挂载成功；
- 测得：子路径不存在时在时限内报错，或实例启动后该目录已被创建；
- 声明：平台是否向未声明卷的实例自动挂载目录。

### C9 执行通道鉴权

**要求**

1. 执行通道对所有到达路径都校验按实例下发的凭证：经平台网关、从其他实例经地址直连、实例内经本地回环；网关鉴权不能替代后两条路径上的鉴权；
2. 凭证由平台为每个实例生成，经控制面交给调用方（例如创建响应，或由网关代为附加），不出现在平台的查询接口中；
3. 凭证不出现在业务进程的环境中，包括经执行通道启动的命令所继承的环境。

只"支持"凭证、但平台不为每个实例生成与下发的，不满足本项。

**类别**：安全。

**为什么需要**：同一 trial 的服务之间网络互通（C4）。执行通道若不鉴权，trial 内任何服务都能以 root 在其他服务里执行命令——agent 攻破一个服务就能越过任务的权限边界；
本地回环这条路径则让一个以非 root 运行的服务在自己的实例里取得 root。两者都可能让判分失真。

**验收**（测得）：不带凭证的请求从三条路径都被拒绝；业务进程与经执行通道启动的命令的环境中、平台查询结果中都找不到凭证。

### C10 资源限制

**要求**

1. 内存上限等于给定值：超过时进程被 OOM，而不是被放宽；
2. CPU 上限不低于给定值；部署声明 CPU 的实际执行方式（例如"上限为给定值的 2 倍"）；
3. 磁盘的默认配额由部署声明。

**类别**：1 必需；2、3 降级。

**为什么需要**：内存上限决定 OOM 行为，与 Compose 声明的限制不一致会改变任务的结果。CPU 给多了不影响正确性，只影响不同部署之间耗时与超时行为的可比性，
所以 flotilla 把实际倍数记进能力报告与每个 trial 的元数据，而不拒绝部署。

**验收**（测得）：实例内读取 cgroup：内存上限等于给定值；CPU 上限不低于给定值，记录实际倍数。

### C11 容量

**要求**：部署声明以下容量，并在使用方目标负载的切片上压测确认。flotilla 据此设置限流、连接池与进程数。

| 量 | 声明与验证内容 |
|---|---|
| 存活实例数 | 可同时存活的实例总数；需求约为并发 trial 数 × 平均服务数，另加锚点 |
| 创建与删除 | 持续速率、并发请求数、排队与限流行为 |
| 互联与策略更新 | 持续速率、规则数与成员数上限、数据面生效时限 |
| 执行与文件 | QPS、并发长命令连接数、上传下载上限 |
| 按 ID 查询 | QPS、延迟与限流行为 |
| 按标签列出 | QPS、结果可见时限；单次延迟随存活实例数增长的关系 |
| 配额与限流 | 超限时返回可区分的限流或容量错误 |

**类别**：规模。

**验收**：用实际任务测量服务数、时长、控制面调用与资源占用；在目标存活数量下复核上述容量。
项目不预设固定规模，也不把估算值当作经过验证的容量。

### C12 诊断

**要求**：失败与长时间等待的实例带可读的原因（镜像拉取失败、调度失败、资源不足、卷挂载失败）；可以取得容器日志或事件。

**类别**：降级。

**为什么需要**：失败原因决定 flotilla 报告的错误是否可重试；没有原因时只能按状态与超时推断，可重试的判定变粗。

**验收**（测得）：用不存在的镜像、超出配额的资源请求、不存在的子路径各创建一次，原因可以区分。

### C13 平台基础设施访问

**要求**：平台为自身运行隐式放行的访问（DNS、元数据、镜像拉取等），由部署完整声明目标、端口与协议。

**类别**：必需。

**为什么需要**：这些访问不受 flotilla 给出的出站策略约束，flotilla 也撤销不了。只有知道它们是什么，才能说清 `none` 与 Compose `internal` 网络的实际范围，
并判断哪些任务的语义因此受影响（例如声明"不能联网"的任务实际仍能访问某些地址）。

**验收**

- 声明：隐式放行的完整清单；
- 测得：`none` 策略下，清单中的每个目标按声明的端口与协议可达；另抽测一组不在清单中的目标，全部不可达。

### C14 可选运行时能力

| 子项 | 依赖它的 Compose 字段 | 类别 |
|---|---|---|
| 隔离的特权运行时（例如 sysbox）与有限设备（`/dev/fuse`、`/dev/kvm`） | `privileged`、`cap_add`、`sysctls`、`devices` | 功能 |
| 附加组、逐命令的能力集、rlimit | `group_add`、`cap_drop`、`security_opt`、`ulimits` | 功能；首版不使用 |
| 伪终端、保持 stdin | `tty`、`stdin_open` | 功能；首版不使用 |
| `/dev/shm` 大小、只读根文件系统、tmpfs 卷 | `shm_size`、`read_only`、`tmpfs` | 功能；首版不使用（tmpfs 以清空的本地目录等效） |
| 设置实例自身的主机名 | `hostname`、`domainname` | 降级；首版不使用 |

"首版不使用"的子项，平台提供了也暂不使用；依赖它们的任务在首版中按 `Architecture.md` 4.6 节处理（拒绝或告警）。

**验收**（测得）：按子项逐一测试，结果写入能力报告。

### C15 镜像来源

**要求**：从私有镜像仓库按 digest（`repo@sha256:…`）拉取；训练时不访问公共仓库。

**类别**：必需。

**为什么需要**：同一任务在所有 trial 中用同一份镜像；训练时访问公共仓库既慢又不可控。

**验收**（测得）：以 `repo@sha256:…` 创建实例成功。

### C16 多容器实例

**要求**

1. 一个实例由多个镜像的容器组成，各有自己的根文件系统，共享同一个网络 namespace（同一地址、同一回环、同一端口空间）；
2. 可另外共享 PID namespace（互相可见进程、可发信号）；
3. 可另外共享 IPC namespace；
4. 每个成员容器经 C2 的执行通道单独可达（按容器指定 argv、身份、工作目录、环境、卷）；
5. 整个实例是 C4、C5、C7 意义上的一个成员：占一个地址，按这个地址加入拓扑与入站隔离。

**类别**：功能；首版不使用。依赖它的任务（Compose 中 `network_mode: service:X`、`pid: service:X`、`ipc: service:X`）在首版中被拒绝。

**为什么需要**：C4 把**独立的**实例连成网络，做不到共享 `127.0.0.1`，PID 与 IPC 更不能跨实例共享。这类 Compose 字段只能由多容器实例承载。
flotilla 不用嵌套容器（在一个特权实例里运行 `docker compose`）代替：那会把互联、出站、资源限制与诊断挡在平台视野之外。

**验收**（测得）：两个镜像组成一个实例、声明共享 PID：从 A 容器看得到 B 容器的进程；两个容器都能连到 `127.0.0.1:<B 的端口>`；对每个容器单独执行命令，读回各自的根文件系统；
该实例以单一地址被另一组成员按 C4 连通、按 C5 隔离。

## 5 不要求平台提供的

以下能力 flotilla 不需要；平台提供了也不会被使用：

| 不要求 | 原因 |
|---|---|
| 业务端口发布、入口代理、泛域名 | 服务之间经 C4 直连，控制面只经执行通道 |
| 组内 DNS、服务名解析 | 用每个实例的 `/etc/hosts` |
| 模板、快照、预热池 | 按镜像直接创建；单个 trial 2 小时以上，启动速度不是主要矛盾 |
| "组"对象与级联删除 | 回收靠标签、TTL 与锚点（C1）；平台提供后可以简化回收，但不是前提 |
| 卷删除接口 | 目录经锚点删除（C8 第 6 条） |
| 平台侧的健康检查与重启 | 由 flotilla 按 Compose 语义执行 |

以下能力首版不要求，`Architecture.md` 第 17 节的扩展会用到；平台提供时记入能力报告供评估：

| 首版不要求 | 用于 |
|---|---|
| 停止后台进程时指定信号与宽限期；主进程退出时清理整个进程树；进程退出事件 | 在运行中按 restart 策略重启服务 |
| 停止实例内除执行通道与入口之外的全部进程，返回时已终止 | Harbor 独立验证模式的逐服务停止 |
| 以相同成员在运行中替换拓扑；在运行中替换外部策略且不使仍被允许的域名失效 | Harbor 在阶段之间切换网络策略 |
| `allowlist` 按协议、端口与 TLS SNI 限定；隐式放行限定到所需端口（DNS 只放行 53） | Harbor 的 `allowlist` / `no-network` |

## 附录 A 能力报告

`flotilla probe` 对一个部署运行第 4 节的验收，写出能力报告（`deployments/<部署>.json`，schema 在 `src/flotilla/capabilities.py`），
记录 endpoint、时间、probe 版本与每项结果。每项带来源：`probed`（测得，附证据）或 `declared`（部署者声明）；判定规则不因来源而异。

flotilla 在启动时读入能力报告：**必需项**任一不满足时报告为"不可用"，flotilla 拒绝使用该部署；**安全项**不满足时默认拒绝，除非配置中显式接受；
**功能项**由扫描器逐任务判断；**降级项**只标出。

必需项清单：C1；C2；C3；C6 第 1、4 条，以及第 2、3 条至少其一；C8 第 1、3、6 条；C10 第 1 条；C13；C15。单服务任务与多服务任务共用这份清单。

报告字段与本文编号的对应（编排核心使用的 `Capabilities` 只取其中一部分，见 `Architecture.md` 2.2 节）：

| 能力 | 报告字段 |
|---|---|
| C1 | `lifecycle.*`；`list_visibility_s` 为声明的 T |
| C2、C3 | `exec.*` |
| C4、C5、C6、C7、C13 | `network.*` |
| C8 | `storage.*` |
| C9、C10、C12、C14、C15、C16 | `runtime.*`；C10 拆为 `memory_limit`（第 1 条）与 `cpu_limit`、`cpu_limit_ratio`（第 2 条） |

C11 的数值由部署者声明，在 M0 压测中确认，不进入报告的判定。

## 附录 B 要求从哪里来

这些要求由 `Architecture.md` 的以下设计推导而来；设计改变时本文随之修改：

| 设计（`Architecture.md`） | 由此产生的要求 |
|---|---|
| 每个服务一个 sandbox，sandbox 内不运行 Docker | 实例之间按组互联（C4）、稳定地址（C7）、跨节点共享存储（C8） |
| sandbox 内不运行 flotilla 的进程，控制面只经平台执行通道 | 执行与后台进程（C2、C3）、执行通道鉴权（C9） |
| 服务名解析用每个 sandbox 的 `/etc/hosts`，不运行 DNS | `/etc/hosts` 可写且不被重写（C2）、地址稳定（C7） |
| 网络语义交给平台的组内互联，flotilla 只给出拓扑，不在 trial 中探测 | C4、C5、C6，且生效可确认 |
| 回收靠标签、有限 TTL 与锚点心跳 | 按标签列出且在时限内完整、续期（C1） |
| 健康检查与退出检测由训练侧经执行通道驱动 | 执行调用容量（C11） |
